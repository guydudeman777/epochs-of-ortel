# Big push, 2026-11-08

Six asks: Bannerlord-style map controls, kheth and merrow towns, better ground, walking in towns, a wide clothing set
(underwear up), and many more UI tabs. One lead (me) plus four agents.

## Hard facts found first

- **Not a git repo.** No worktrees, no branches. All five work in one folder. So every file has one owner (below).
  Strongly want `git init` + first commit before anyone starts, so a bad edit can be undone.
- Map controls now: WASD steers the band, Q/E turn, right-drag turns, wheel zooms, left click moves / chases / enters.
  All of it lives in `overworld_scene.gd` (1213 lines), which three lanes want. Lead splits it first.
- Ground is vertex colour only (`OverworldLand._ground_material`, one `StandardMaterial3D`). No textures.
- `TownView.kit_for` gives merrow (`reef`) the tidebound kit and kheth (`hive`) the sunborn kit. No own models.
- Town "inside" is a text menu (`_open_town`: work, band, recruit, captives, land). No walk scene.
- Clothes: `EquipmentData` = `weapon_id`, `has_shield`, `armour_ids`. Eight `ArmourDef`s. `build_mh_body.py` grows six
  garments off the base mesh (shirt, trousers, boots, mail, surcoat, coif) plus a helmet, each with a skin-hide bit.
  No slots, no layers, no gloves, hats, underwear.
- `InventoryData` = gold + goods. Items are not things you hold yet.
- No quests anywhere in the sim.

## Step 0, lead only, before agents start

Shared contracts, so the lanes never wait on each other or touch the same file.

1. Split `overworld_scene.gd`:
   - `src/view/overworld/overworld_controls.gd`: input, camera, steering, click picking. (Lane A owns after.)
   - `src/view/overworld/overworld_scene.gd`: clock, tokens, town redraw, menus. Gets a hook
     `enter_town(site)` that today opens the text menu. (Lane C swaps it for the walk scene.)
   - `src/view/ui/`: new panel host. `overworld_scene` only calls `GamePanels.toggle(&"party")` etc. (Lead owns.)
2. Clothing data contract (Lane D builds on it, Lane E/UI reads it):
   - `GarmentDef` (in `src/defs/`): `id`, `display_name`, `slot`, `layer`, `covers`, `stops`, `warmth`, `weight`,
     `value`, `model` (garment mesh name), `hides` (skin bits), `culture_ids`, `tech_id`, `colors`.
   - Slots: `underwear_top`, `underwear_bottom`, `shirt`, `trousers`, `body_armour`, `over` (surcoat/coat/robe),
     `head`, `head_armour`, `hands`, `feet`, `cloak`, `belt`.
   - `ArmourDef` folds into `GarmentDef` (same `covers`/`stops` so `LimbService` and `BattleResolver` keep working).
   - `EquipmentData.worn: Dictionary[StringName, StringName]` slot -> garment id. Old `armour_ids` read once on load
     and moved over (bump `CURRENT_SAVE_VERSION`).
   - Items as things: `InventoryData.items: Dictionary[StringName, int]` (garment / weapon id -> count). Goods stay.
   - All wear changes go through `Actions.wear(ctx, who, garment_id)` / `Actions.take_off(ctx, who, slot)`.
3. Quest contract (lead builds): `QuestData` in `WorldState.quests`, made by a `QuestSystem` from real world state
   (a lord wants a band hunted, a town wants grain, a family wants a captive bought back). NPCs can take them too.
4. Town walk contract: `TownSite` (pure data, in `src/sim/`) says what spots a town has: market, tavern, hall,
   smith, barracks, slave pen, gate, each tied to the real thing behind it (businesses, ruler, troops, captives).
   Lane C draws it, the text menu also reads it, so the menu and the walk scene always agree.

Lead writes stubs for all of the above that compile and pass tests, then lets the agents go.

## Lanes

Each agent owns only its files. Need something in another lane's file: message the lead, do not edit it.

### Lane A: map controls + ground (agent 1)

Owns `overworld_controls.gd`, `overworld_land.gd`, new `src/view/overworld/*.gdshader`, `assets/textures/ground/`.

- Bannerlord map controls:
  - WASD / arrows pan the camera, not the band. Edge-of-screen pan (can turn off).
  - Q/E or middle-drag (also right-drag) turn the view. Wheel zoom, smooth, with tilt that lowers near the ground.
  - Left click on ground = travel there. Hold left = keep following the cursor. Click band = chase / meet,
    click town = go and enter.
  - Space = pause / play. 1 / 2 / 3 = pause, play, fast. Time runs only while the band moves (as Bannerlord), unless
    held to fast.
  - Camera follows the band; panning frees it; `F` or the band's portrait snaps back.
  - Pad: left stick pans, right stick turns/zooms, A = travel to cursor point.
  - Hotkeys for panels sent to `GamePanels`: C char, I inventory, P party, K kingdom, L clan/family, J quests, N book.
- Ground textures: one shader on the ground mesh. Splat by the existing vertex colour + kind + biome: grass, tilled
  field, dirt, sand, rock, snow, ash, mud, shore, road. Triplanar on slopes so cliffs are rock. Distance blend so
  near is detailed and far is the old colour (no tiling seen from high). Tiles made in Blender/numpy like
  `build_gear_textures`, never downloaded. Better water: depth colour, shore foam.
- Done: `--demo` still plays; screenshot side by side old vs new at three zooms and in each biome.

### Lane B: kheth + merrow towns, and walkable town art (agent 2)

Owns `tools/art/build_towns.py` (new functions only, plus the build list), new `assets/models/*` it makes,
`TownView.kit_for` lines for `reef` and `hive`.

- Merrow (`reef`): stilt and coral-stone houses on the wading flats, drying racks, shell-and-kelp roofs, a tide hall
  half in water, coral/driftwood palisade, a lantern tower.
- Kheth (`hive`): hive mounds of resin and sand, cell-wall houses, a great spire hive as the seat, chitin-plate
  walls, spined towers. Low doors, few windows.
- Each: small house, big house, seat, low wall, high wall, two towers. Same `Kit` shape as the others.
- Then walkable versions for Lane C, shared by every people: each kit's house, hall and wall at person scale with
  real doors that open into a few interiors (tavern, hall, smithy, market stalls, pen). Collision as simple boxes
  named `*_col` so Godot makes static bodies on import.
- Done: `face_test`-style viewer shows each new model; map shows reef and hive towns in own look.

### Lane C: walk in towns (agent 3)

Owns new `src/view/town/` (scene, player walker, NPC crowd, interact prompts), `TownSite` drawing, the
`enter_town` hook body.

- Enter a town on the map -> load `town_scene.tscn` built from that town's real data: its kit, its lots and streets
  (reuse `TownView` layout at person scale), its walls by `fortification`, its business yards.
- Player walks as their real body (`BodyView`, `LegLayer` with the ease stance, third person). Reuse
  `FightControls` input code for mouse / keys / pad where it fits.
- Spots do real things, all through `Actions`, the same calls the text menu uses now:
  - Market: buy/sell goods and clothes (uses Lane D items).
  - Tavern: hire, rumours (from the chronicle), recruits, quests from Lane E.
  - Hall: meet the lord (real `CharacterData`), ask for work, swear fealty, buy freedom.
  - Smith/armourer/weaver: buy gear made by the real business.
  - Barracks/gate: recruit, form band, leave.
  - Pen: sell / buy captives (only where law allows).
- People seen are real: named characters in town walk about; the rest are crowd drawn from the town's pop groups.
  The world clock stays paused inside, or runs slow (decide with lead).
- Done: enter, walk, do each spot, leave, back on the map with the result applied. Test for the `TownSite` data.

### Lane D: clothing (agent 4)

Owns `tools/art/build_mh_body.py` garment code, `src/view/face/body_view.gd` dressing code, `content/defs/garments/`,
`tools/generate_content.gd` garment part, garment rules in `LimbService` / `BattleResolver` only where armour was read.

- Garments grown off the base mesh like now, so all body shapes fit. Plus rigid pieces (helmets, plates) on bones.
- Set to build (each with 2-4 cuts and culture looks):
  - Underwear: loincloth, braies, breast band, shift/chemise, smallclothes. Always worn under; never naked in the
    sim view by default.
  - Shirts, tunics, gowns, robes, coats, jerkins, doublets, kaftans, desert wraps, furs.
  - Trousers, hose, skirts, kilts.
  - Shoes: sandals, turnshoes, boots short and tall, fur boots, sabatons.
  - Gloves: cloth, leather, fur mitts, mail mittens, gauntlets.
  - Hats: hood, cap, felt hat, turban, fur hat, straw hat, veil, crown/circlet.
  - Armour: padded, leather, brigandine, lamellar, scale, mail, coat of plates, plate, helmets of each age (to the
    gunpowder era: morion, cabasset, buff coat), cloaks, belts.
- Layers hide skin and inner layers by bits, as now, so nothing pokes through.
- Colours and wear from the owner's culture and wealth. Kheth and merrow: own pieces later (form bodies wear none
  now); keep the slot data race-blind.
- AI and NPC kits: each `TroopDef` and each class of person gets a default outfit by culture and wealth.
- Done: a viewer (`face_test --view=wardrobe`) cycles every garment on male, female, thin, heavy, old, young;
  battles still show the right armour; soak passes.

### Lead: UI tabs, quests, glue (me)

Owns `src/view/ui/`, `QuestData`, `QuestSystem`, the step 0 contracts, `tests/`, `CLAUDE.md`.

- Panels, one shared look (`menu_style.gd`, `hud_plate.gd`), each opened by hotkey or a top bar:
  - Character: body, skills, traits, wounds and lasting damage, legal status.
  - Inventory: paper doll by slot, items, gold, goods; wear/remove via `Actions`.
  - Party: troops, prisoners, food, morale, wages; upgrade, release, sell.
  - Clan / family: dynasty tree, spouse, children, heir, deaths. Shows who you become on death.
  - Kingdom: realm, ruler, laws (bondage too), towns, wars, armies, relations with other realms.
  - Quests: open, done, failed, with who gave them and why.
  - Book: every known person, town, realm, people (encyclopedia).
  - Chronicle: the news log as a tab.
- `QuestSystem` in the daily tick, deterministic, saved, fair to NPCs.
- Merge, run tests and soak after each lane lands, update `CLAUDE.md`.

## Risks

- One folder, five writers: file ownership above is the only guard. Git makes it safe.
- Art build overwrites `.glb` files: B and D both run Blender. Run `build_all.py -- towns` and `-- body` only, never
  the full build, while the other lane is building.
- `body_mh.glb` grows big with many garments; may need to split garments into their own `.glb`.
- Save break: equipment change bumps the save version with a move-over on load.
- Day already slower than 4 ms. Quests and wardrobe AI must not add much; check per-system timing in the soak.
